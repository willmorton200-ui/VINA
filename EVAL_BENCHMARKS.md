# VINA Scanner — Ветка бенчмарков и тестов (`eval-benchmarks`)

Данная ветка содержит полный комплект тестовых наборов данных, валидационных манифестов, эталонной разметки (`mapping.json`) и раннеров для оценки точности и скорости сервиса VINA.

---

## 📁 Структура тестовых пакетов

```text
VINA/
├── eval/                     # Официальный финальный тест организаторов (100 бутылок)
│   ├── queries/              # 100 контрольных фото этикеток (eval_photo_001..100.webp)
│   ├── queries.tsv           # Идентификаторы и список файлов
│   ├── mapping.json          # Истинные правильные ответы (Ground Truth)
│   ├── checksums.sha256      # Контрольные суммы файлов
│   └── README.md             # Регламент организаторов
│
├── owner_eval/               # Внутренние тестовые наборы и полевые испытания
│   ├── 1/                    # Прогон 1: 27 каталожных фото + mapping.json
│   ├── 2/                    # Прогон 2: 25 сложных полевых фото (блики, тени) + mapping.json
│   ├── 3/                    # Прогон 3: 19 фото
│   ├── 119/                  # 119 расширенных полевых фото
│   └── run_participant_eval.py # Альтернативный валидатор
│
├── test_vina_scanner.py      # Главный раннер оценки точности (Hit@1, latency)
├── run_eval.sh               # Универсальный скрипт запуска для Linux / Docker
├── запустить_тест_D_Eval.bat # Батник запуска теста 100 бутылок для Windows
├── запустить_тест_сканера_прогон_1.bat # Батник запуска Прогона 1 (каталожные 27 фото)
└── запустить_тест_сканера_прогон_2.bat # Батник запуска Прогона 2 (полевые 25 фото)
```

## 🚀 Как клонировать эту ветку на сервер или ноутбук

Основная ветка `main` намеренно оставлена чистой и легковесной. Чтобы скачать проект вместе со всеми тестами:

```bash
# Клонирование сразу нужной ветки:
git clone -b eval-benchmarks https://github.com/willmorton200-ui/VINA.git
cd VINA
```

Или переключение в уже существующем репозитории:
```bash
git fetch origin
git checkout eval-benchmarks
```

## ⚙️ Порядок запуска тестирования

### Шаг 1. Запуск сервиса VINA
Убедитесь, что бэкенд запущен и отвечает на порту 8080:

* **В Docker:**
  ```bash
  docker compose up -d
  ```
* **Или локально на Windows / Linux:**
  ```bash
  python app.py
  # или двойным кликом по start_app.bat
  ```

---

### Шаг 2. Запуск тестов

#### Вариант A. На Windows:
Просто запустите нужный `.bat` файл двойным кликом:
* **`запустить_тест_D_Eval.bat`** — тест 100 контрольных бутылок (`eval/`)
* **`запустить_тест_сканера_прогон_1.bat`** — 27 каталожных фото
* **`запустить_тест_сканера_прогон_2.bat`** — 25 полевых фото

#### Вариант B. На Linux / macOS / в Docker:
```bash
# Тест 100 бутылок:
./run_eval.sh eval

# Прогон 1 (27 фото):
./run_eval.sh 1

# Прогон 2 (25 фото):
./run_eval.sh 2

# Стресс-тест 119 фото:
./run_eval.sh 119
```

#### Вариант C. Через Python напрямую:
```bash
# 100 бутылок через HTTP API:
python test_vina_scanner.py --eval-root ./eval --mode http

# Если сервис запущен на удаленном сервере:
python test_vina_scanner.py --eval-root ./eval --endpoint http://<IP_СЕРВЕРА>:8080/v1/eval/predict
```

## 📊 Результаты и отчёты

После завершения тестирования:
1. В консоль выводится сводная таблица:
   * **Точность Hit@1**: процент совпавших `slug` с эталоном из `mapping.json`.
   * **Время отклика (Latency)**: среднее, минимальное и максимальное в миллисекундах.
2. В папку `eval_results/` и в корень тестового пакета сохраняется файл:
   ```text
   predictions.jsonl
   ```
   в стандарте организаторов конкурса (`query_id`, `image_path`, `predicted_slug`, `latency_ms`).
